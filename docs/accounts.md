# Accounts and sign-in

Adding accounts, signing in to each provider, signing out and removal, and how credentials are
handled. Overview: [README](../README.md).

## Adding accounts

On a fresh install, click the **AI +** taskbar tile to open the settings window, then choose **Add account** and a provider. Adding an account creates it at once, with a default label (`A`, `O`, `G`, `C` or `OC`, then `A2`, `A3`, ...; labels that still have a stored sign-in are skipped, so a new account never reuses an old one), and polls it right away. Its card opens on its label: type a name or keep the default, then press Enter or move to another control, and an Anthropic, OpenAI, GitHub Copilot or OpenCode Go account opens its sign-in window. A label that can't be saved holds the sign-in back until one is saved, and closing Settings first leaves the account showing **Sign-in needed** until you sign in. Antigravity accounts query the local app and record history immediately. Expand an account's card to rename it and choose its taskbar quotas (at least one stays selected). Each provider-and-label pair must be unique. The provider can't be changed later: remove the account and add a new one.

Settings autosave; most appearance and behavior edits don't immediately re-query providers, while new or identity-changed accounts and stale accounts made visible can fetch. When upgrading, existing Windhawk settings are imported once. Updating from a version without per-account identities shows each account's logo beside its bars instead of its label; choose **Label** as the account's identity in **Settings > Accounts** to bring the label back.

## Signing in

The mod runs its own OAuth sign-in and refreshes the access token itself, so the bars keep working without re-running any CLI. A column that needs authentication shows "click to sign in"; left-click it to start the flow. You can also click **Sign in** on the account's card in **Settings > Accounts**, or right-click the column and choose **Sign in**.

Signing in shows a window instead of launching a browser: **Open in browser** uses the default browser, and **Copy link** lets you paste the sign-in link into any browser or profile (handy when each account lives in a different profile).

- **Anthropic**: open the link in a browser on this PC. After you approve on claude.ai, the browser hands the sign-in to the mod on `localhost` (a free port the mod picks each time) and the window closes by itself, so there's nothing to paste. Signing in on another device (or if the redirect fails)? Click **Use a code**: a second window's link leads to a page showing a code like `abc...#xyz...`; paste it into that window and click **Sign in**. A code from another sign-in's link (an earlier attempt's tab, say) is refused and the window stays open for the right one.
- **OpenAI**: open the link in a browser on this PC. The mod catches the redirect on `localhost:1455` (falling back to `1457`) and the window closes by itself, so there's nothing to paste. The window waits until you approve or click **Cancel**; while it is open the port stays busy, so a Codex CLI sign-in at the same time can fail - finish or cancel one first.
- **GitHub Copilot**: the window shows a code instead of a link. **Copy code and open GitHub** copies it and opens `github.com/login/device` in the default browser (or open that page in any browser or profile, on any device, and type the code); sign in to the GitHub account with Copilot and enter the code. The mod checks with GitHub every few seconds, with a status line under the code: "Waiting for approval on GitHub…", or the failure while a check that failed on the network or a GitHub server error is retried (more slowly when GitHub asks to). The window closes by itself once you approve; the code expires after 15 minutes. When the sign-in ends otherwise (approval denied, the code expired, or another failure, which the Windhawk log details), the window stays open with the reason and **Close**. **Cancel** ends it at any time; while a check is under way the window waits for it, then discards its result. A GitHub account without a Copilot plan or seat signs in, then shows "no Copilot access on this GitHub account".
- **OpenCode Go**: there is no browser sign-in; the window takes an API key. **Open in browser** or **Copy link** opens the OpenCode console (`opencode.ai/console`): copy an API key of the workspace with your Go subscription (your own key, for Go Teams), paste it into the masked box and click **Sign in**. The mod saves the key without checking it; the account's next poll does: a rejected key shows "click to sign in" again, and a key whose workspace has no Go subscription shows "no OpenCode Go subscription on this key".
- **Google Antigravity**: no separate mod sign-in is needed. Keep the signed-in Antigravity app or CLI running so the mod can query its local language server. Older IDE builds also need an open workspace.

## Signing out and removing accounts

Use **Sign out** on the account's expanded card in Settings to delete an Anthropic/OpenAI/GitHub Copilot stored token or OpenCode Go key; the card also offers **Sign in again**. Signing out only deletes the mod's copy: an OpenCode Go key stays valid until you delete it in the OpenCode console. Renaming a label preserves its stored sign-in when possible. **Remove account** names the account and asks for confirmation; removing an Anthropic/OpenAI/GitHub Copilot/OpenCode Go account always deletes its stored sign-in. Its recorded usage history is kept unless you check **Also delete its usage history** (offered when it may have some). Sign-ins that earlier versions retained for removed accounts stay stored; renaming a new, signed-out account of that provider to the old label takes one over, and removing that account then deletes it.

## Security

For Anthropic, OpenAI and GitHub Copilot, the mod owns its OAuth credentials end to end: it signs in, stores the access and refresh tokens, and refreshes them itself. OpenCode Go has no OAuth sign-in: the mod stores the API key you paste. Tokens and keys are stored encrypted with Windows DPAPI (current user) in the mod's own Windhawk storage; they are never written to disk in plaintext.

The mod never reads or writes the OpenCode, Claude Code, or Codex credential files, nor any other app's GitHub or Copilot sign-in (Visual Studio, VS Code, the GitHub CLI, Windows Credential Manager). Refresh tokens are used only against the provider token endpoints and are never sent as bearer tokens to the quota endpoints. The mod's requests never follow HTTP redirects, so a token, key or Antigravity's local CSRF token can't be forwarded to another address; a redirect shows as an HTTP error, and the mod's log names where it pointed.

Signing in uses the public OAuth clients of the official CLIs (Claude Code for Anthropic, Codex for OpenAI) with PKCE; while their sign-in window is open, a listener bound only to `127.0.0.1` receives the browser's redirect. GitHub Copilot uses GitHub's device flow with the public client of GitHub's copilot.vim (`Iv1.b507a08c87ecfe98`) and only the `read:user` scope; the mod talks to `github.com` (sign-in and token refresh) and `api.github.com` (the Copilot usage endpoint, `copilot_internal/user`), and opens a browser only when you click **Copy code and open GitHub**. OpenCode Go's key is sent only to OpenCode's usage endpoint (`opencode.ai/zen/go/v1/usage`); the key can also make paid requests on your account, so treat it like a password. Antigravity uses only its signed-in loopback language server and stores no Google token.

Status pages are read without any token, key or cookie, with plain GETs to the four hosts listed under [Provider outages](taskbar.md#provider-outages), and never follow redirects either.

Anthropic's usage and profile requests identify as the Claude Code CLI (its user agent): Anthropic reports free resets only to a recent CLI. Besides the usage endpoints, the mod reads Anthropic's OAuth profile (`api.anthropic.com/api/oauth/profile`, for the plan name, about every 6 hours) and, while a ChatGPT account has free resets, `chatgpt.com/backend-api/wham/rate-limit-reset-credits` for their expiry, both with the account's usage token. It never redeems resets.
